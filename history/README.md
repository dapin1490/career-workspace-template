# 이력 문서 작성 가이드

이력 원본은 두 층으로 나뉩니다. 새 이력은 사람이 직접 입력하고, 정리는 에이전트가 도울 수 있습니다. 사람과 에이전트 모두 이 가이드를 따릅니다.

## 1. 구조

| 위치 | 담는 내용 | 담지 않는 내용 |
|---|---|---|
| `full-resume.md` (진입점) | 기술과 스킬 레벨, 학력, 어학, 수상, 교육, 직무 선호, 인적성, 일하는 방식, **이력 색인 표** | 프로젝트별 세부 사실, 수치, 경위 |
| `history/*.md` (항목 파일) | 프로젝트, 연구, 활동 하나의 모든 세부 사실, 사실 정정 메모, 면접 주의사항 | 다른 항목의 사실 |

- 같은 과정에 속한 항목이 여럿이면 하위 폴더로 묶습니다. 예: `history/bootcamp/`
- 파일 이름: 독립 항목은 `시작연도-주제.md`(예: `2025-patent-competition.md`), 하위 폴더 안에서는 `주제.md`(예: `dt-simulator.md`)
- 빈 항목 템플릿은 `_template.md`에 있습니다. 복사해서 쓰십시오.

## 2. 중복 사실 원칙 (가장 중요)

**하나의 사실은 한 곳에만 상세히 씁니다.** 같은 내용이 두 곳에 있으면, 한쪽만 고쳐지고 다른 쪽은 틀린 채로 남습니다. 예를 들어 프로필 요약 섹션과 항목 본문에 같은 성과를 따로 적어 두면, 시간이 지나며 논문 등재 구분, 수치, 수상 사유가 서로 어긋나기 쉽습니다.

- **상세 사실은 항목 파일에만 씁니다.** 수치, 역할, 경위, 기여도, 피드백, 한계가 여기에 해당합니다.
- **프로필(`full-resume.md`)에는 메타데이터와 경로만 씁니다.** 이름, 기간, 기관, 수상 일자, 그리고 `상세: history/...md` 한 줄입니다.
- **색인 표에도 메타데이터만 씁니다.** 기간, 항목명, 유형, 파일 경로만 적고 성과나 수치는 적지 않습니다.
- **여러 항목에 걸친 사실은 가장 관련이 깊은 파일 한 곳에 씁니다.** 다른 파일에서는 "(○○ 파일 참고)"로 가리킵니다.
- **인적성 서술(강점, 성향, 일하는 방식)은 `full-resume.md`에 씁니다.** 근거 에피소드의 세부 내용은 항목 파일에 두고, 인적성 쪽에는 한두 문장 요약과 출처만 남깁니다.

## 3. 새 이력 추가 절차

1. `history/`에 새 파일을 만들고 `_template.md`의 구성으로 작성합니다.
2. `full-resume.md`의 **이력 색인 표**에 한 줄을 추가합니다. 최신 항목이 위로 갑니다.
3. 수상이나 교육 과정이면 `full-resume.md`의 해당 섹션에 메타데이터 한 줄과 `상세:` 경로를 추가합니다.
4. 새로 익힌 기술이 있으면 `full-resume.md`의 스킬 레벨을 고칩니다. 근거 프로젝트는 파일 경로로만 가리킵니다.

## 4. 항목 파일 구성

필요 없는 칸은 지워도 됩니다. 각 칸에 무엇을 쓰는지는 `_template.md`에 적어 두었습니다.

```markdown
# 항목 이름

- 항목 이름 (YYYY.MM.DD - YYYY.MM.DD)
    - 배경 및 목표 (Situation & Task)
    - 역할 및 행동 (Action)
    - 어려움 및 해결
    - AI 활용
    - 기여도 구분: 팀 규모, 본인 담당, 다른 팀원 담당
    - 결과 및 성과 (Result)
    - 한계 / 받은 피드백
    - 자기소개서 활용 시 주의사항
    - 자료: 블로그, 깃허브, 시연 영상 링크
```

## 5. 작성 규칙

- **직접 확인한 사실만 씁니다.** AI가 만든 자소서나 면접 답변 초안의 문장을 이력 원본으로 옮기지 마십시오. 옮겨야 한다면 원본(후기, 블로그, 코드, 발표자료)과 대조한 뒤 옮깁니다.
- **역할은 정확히 구분합니다.** "총괄", "주도", "설계" 같은 단어는 실제 범위만큼만 씁니다. 본인이 하지 않은 일은 "팀원 담당"으로 명시합니다. AI 에이전트로 구현한 부분은 그렇다고 밝힙니다.
- **수치에는 근거를 남깁니다.** 출처(논문 표, 테스트 로그, 발표자료)를 함께 적습니다. 기억에 의존한 수치는 "(기억, 기록 없음)"을 붙입니다.
- **정정할 때는 본문을 고칩니다.** 면접 방어를 위해 정정 경위가 필요하면 `[사실 정정 (YYYY-MM-DD)]` 메모를 남깁니다.
- **대외에 쓰지 않을 내용은 표시합니다.** 동기, 갈등의 속사정처럼 대외에 쓰지 않을 사실은 `(내부 메모, 대외 비공개)`를 붙입니다. 공식 이력으로 쓰지 않을 경험은 `(공식 이력으로 쓰지 않음)`을 붙입니다.
- **비밀유지 대상은 기록하지 않습니다.** 유출 금지 조항이 있는 채용 과제 등이 해당합니다.

## 6. 출처 표기 규칙

AI가 쓴 글과 사람이 쓴 글을 구분하기 위한 규칙입니다. 면접 노트처럼 둘이 섞이는 문서에서 AI가 지어낸 수치나 경험이 이력 원본으로 흘러드는 것을 막습니다.

- **라벨은 AI가 붙입니다.** 라벨이 없는 글은 사람이 쓴 글로 간주합니다. 에이전트는 `Artifacts/` 밖의 문서에 글을 쓸 때 반드시 아래 라벨을 붙입니다.
- `Artifacts/` 안의 파일은 파일 전체가 AI 산출물이므로 개별 라벨 대신 파일 상단에 "에이전트 산출물"이라고 한 줄만 적습니다.

| 라벨 | 의미 | 이력 원본(`full-resume.md`, `history/`)의 근거로 사용 |
|---|---|---|
| (라벨 없음) | 사용자가 직접 쓴 글 | 가능 |
| `[AI 초안]` | 에이전트가 썼고 아직 사람이 검수하지 않은 글 | **불가** |
| `[AI 초안 → 검수 (YYYY-MM-DD)]` | 사용자가 읽고 사실과 맞다고 확인한 글 | 가능 |
| `[출처: 경로 또는 URL]` | 다른 문서, 논문, 블로그에서 옮긴 사실 | 가능 (출처를 함께 남김) |
| `(기억, 기록 없음)` | 증빙 없이 기억에 의존한 사실 | 가능. 단, 대외 문서에서는 단정하지 않음 |
| `(사용자 답변 YYYY-MM-DD)` | 에이전트가 질문하고 사용자가 답한 내용을 옮긴 사실 | 가능 |

**섞인 문서의 표기법** (면접 노트, 예상 질문지 등): 질문 하나 아래의 하위 항목 이름을 고정합니다.

```markdown
- [질문] 리더형과 팔로워형 중 어느 쪽인가?
    - **대답 메모**: (사용자 답)
    - **[AI 초안] 답변 제안**: (에이전트 답)
    - **[AI 초안] 피드백**: (에이전트 피드백)
```

- AI 제안을 고쳐 자기 답으로 채택했다면, 그 내용을 '대답 메모'로 옮겨 적고 AI 제안은 지웁니다. 둘 다 남기면 어느 쪽이 최종인지 헷갈립니다.
- 서브에이전트나 다른 AI가 요약한 내용은 원본 문서에 반영하기 전에 원문을 직접 열어 대조합니다. 요약 과정에서 원문에 없는 문장이 섞이는 일이 실제로 있습니다.

## 7. 정정 체크리스트

원본 사실을 정정할 때마다 아래 순서를 따릅니다. 사실은 **원본 → 파생 문서** 방향으로만 흐릅니다. 파생 문서는 포트폴리오, 자소서, 이력서, 면접 노트입니다. 파생 문서를 쓰다가 새 사실이 필요해지면 먼저 `history/`에 적고, 그다음에 파생 문서에 씁니다.

1. `history/` 해당 파일의 본문을 고칩니다. 필요하면 `[사실 정정 (YYYY-MM-DD)]` 메모를 남깁니다.
2. **고치기 전 표현**(틀린 수치, 과장된 단어)으로 아래 범위를 전체 검색합니다.
    - `JD/`의 진행 중인 공고, `JD/Submitted/` 중 전형이 아직 진행 중인 공고
    - `interview-records.md`
    - 포트폴리오 원본 (`Artifacts/portfolio/`, 포트폴리오를 별도 저장소로 관리한다면 그 저장소)
3. 고칠 수 있는 파생 문서는 고칩니다. 별도 저장소는 그 저장소에서 따로 커밋합니다.
4. 고칠 수 없는 제출본(제출 완료된 자소서, 이력서, PDF)에서 발견되면, 해당 공고 메인 문서의 **'제출 서류 리스크 메모'** 섹션에 기록합니다. 전형이 끝난 공고는 기록하지 않아도 됩니다.
5. 커밋 메시지를 `정정:`으로 시작합니다. `git log --grep=정정`으로 정정 이력만 모아 볼 수 있습니다.
