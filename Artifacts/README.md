# Artifacts 폴더 관리 규칙

특정 공고에 속하지 않는 에이전트 산출물을 보관하는 곳입니다. 특정 공고에 속한 산출물은 그 공고 폴더의 `Artifacts/`에 둡니다(`JD/README.md`).

에이전트는 이 폴더에 새 파일을 승인 없이 만들 수 있습니다(`AGENTS.md` 행동 규칙 4번). 초안과 보고서는 여기에 쌓이고, 이력 원본은 사용자가 승인한 변경으로만 바뀝니다.

## 1. 분류

산출물이 **무엇을 바꾸려는 문서인가**로 나눕니다.

| 폴더 | 담는 것 | 예 |
|---|---|---|
| `maintenance/` | 이 저장소와 이력 원본(`full-resume.md`, `history/`)의 관리: 업데이트 검토, 규칙 제안, 구조 개편 계획, 이력 항목 초안 | `2026-11-02_이력항목_초안_캡스톤.md` |
| `strategy/` | 여러 공고에 걸친 지원 전략: 지원 우선순위, 직무 탐색, 역량 공백 분석, 재사용 문안 | `2026-11-05_지원_우선순위_분석.md` |
| `portfolio/` | 포트폴리오 콘텐츠: 프로젝트 본문 초안, 서술 검토 | `2026-11-10_포트폴리오_서술_검토.md` |
| `archive/` | 반영 완료 또는 폐기된 산출물. 안쪽도 위 세 분류를 그대로 따름 | `archive/maintenance/` |

- 포트폴리오를 별도 저장소(웹사이트 등)로 관리하더라도, 콘텐츠 산출물은 이곳에 둡니다. 이력 원본과 내부 메모를 근거로 쓰기 때문에 원본 옆에 있어야 대조하기 쉽습니다.
- 세 분류 어디에도 맞지 않는 산출물이 반복해서 생기면 새 분류 폴더를 만들고 이 표에 추가합니다.

## 2. 상태 표기

모든 산출물의 제목 바로 아래에 상태 줄을 둡니다.

```markdown
> 상태: 진행 중
> 상태: 반영 완료 (YYYY-MM-DD, 관련 커밋 해시)
> 상태: 보류 (보류 사유 또는 보류 중인 부분)
> 상태: 폐기 (사유)
```

- 일부만 반영된 경우는 "진행 중"이나 "보류"로 두고, 반영된 부분과 남은 부분을 상태 줄에 짧게 적습니다.

## 3. 아카이브

- **반영 완료**나 **폐기**가 되면 `archive/`의 같은 분류 폴더로 옮깁니다. 활성 폴더에는 지금 다룰 문서만 남깁니다.
- **보류**는 옮기지 않습니다. 언젠가 다시 다룰 문서이기 때문입니다.
- 이동은 `git mv`로 하고, 내용 수정과 다른 커밋으로 나눕니다.

## 4. 파일 이름

- 새 산출물은 `YYYY-MM-DD_주제.md`로 짓습니다. 날짜순으로 정렬되고, 같은 주제의 후속 문서와 구분됩니다.
